# 2026-10-29 23:45 CDT - #87 follow-ups: an unread diff fails closed, git that cannot run is not "untrusted"
- **Who:** PromptBuilder seat (Claude Opus 5.5), at Daedalus's request after #87 merged (a62007f).
- **Change:**
  - `DiffStats.readable` is False when git could not produce the diff. The confidence gate turns that into `diff_unreadable`, a policy escalator: it forces human review, cannot be disabled, and is in the audit. Before this, an unreadable diff read as "nothing changed" (the #87 CI long-path failure).
  - `GitUnavailable` (a config-read timeout) is handled before `UntrustedRepo` wherever the daemon caught that. At worker prep the card rolls back to backlog. After the worker ran (integration, verify clone, merge gate), the card blocks with `error: git_unavailable` and a reason that says the repo is unchanged. It was being told to re-trust a repo that had not changed.
  - V3-1: a daemon clone's baseline refuses config keys outside what `git init`, `remote add` and the push write. `branch.*.remote` must be `origin`. `objects/info/alternates`, `http-alternates` and `info/attributes` are refused at trust and at every daemon git call; the fingerprint does not cover them.
  - V3-5: the second (reverse) hunk after each `GIT binary patch` counts its N, not its delta's result size. A forward apply never builds that result, so counting it refused real patches whose old blob was large. Any hunk past the second still counts in full.
- **Why:** each of these was a gate input or refusal that could be wrong without saying so: an empty diff that was really unread, a "re-trust the repo" message for a timeout, and a baseline that trusted whatever was in the clone at that moment.
- **Decision:** after the worker, block rather than requeue. The model work is already spent, and with git staying down a requeue would rerun the paid worker on every poll. A test pins one spawn and no respawn over three polls; a mutant that requeues fails it.
