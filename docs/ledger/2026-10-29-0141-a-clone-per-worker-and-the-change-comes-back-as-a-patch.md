# 2026-10-29 01:41 CDT - a clone per worker, and the change comes back as a patch
- **Who:** PromptBuilder seat (Claude Opus 5.5), the R1/R2 work Daedalus asked for after #86 (worker isolation options doc C:\dev\_status\WORKER_ISOLATION_OPTIONS_2026-10-28.md).
- **Change:**
  - SandboxLauncher seam (`common/sandbox.py`): the worker spawn and the verifier's shell ACs both start through it. The daemon now ends the whole Job Object on every worker exit (kill_tree returned early once the leader exited, so a child the model left running survived), and the job no longer permits breakaway.
  - R1: each attempt gets a throwaway clone of the project (`--no-hardlinks --single-branch --no-tags`) at a base sha pinned at claim, with no remote. `git worktree add`, its mutex, its verification and the prune sweep are gone; `--worktree-prune` is accepted and ignored.
  - R2: the worker writes `result.patch` plus a sha256 done marker, using git with the hardened env (no API key, no global or system config, no hooks). After the worker's job has ended the daemon applies the patch to the index of its own integration clone, refuses any path that is absolute, contains `..`, a backslash or a colon, or aliases `.git` (case, trailing dots or spaces, 8.3 names), and any symlink or submodule, and commits once with the identity pinned at boot. The same check runs again on the committed tree, because the index is not fingerprinted and a sibling worker could rewrite it.
  - The verifier runs in a third clone detached at that sha. The merge gate re-checks the integration clone's trust baseline, pushes `<sha>:refs/heads/<branch>` from it, and fails closed with no integrated commit.
  - git_safety: protectNTFS and protectHFS overrides, `extra_config`, memory-only trust for daemon clones, `commit_identity()`. The exit-time trust check of the worker's tree is removed (that tree is untrusted by construction). RUNNER_CONTRACT.md, the tier-3 path list and AUTO_MERGE.md are updated to match.
- **Why:** with a git worktree the worker shared the project's `.git`, and the daemon's verify, diff and push all ran git in that worker-written tree. The #85 and #86 trust hash detected tampering there but could not stop git from reading it. Now the daemon runs git only in the project (the trusted clone source) and in clones whose config it wrote.
